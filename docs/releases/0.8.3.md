# Poor Man's Text 0.8.3

This maintenance release hardens document conversion against changing or
malformed input, limits generated spreadsheet output, and closes two cleanup
gaps after an interrupted installation.

## Conversion safety and correctness

- DOC conversion now copies the source once and revalidates those exact staged
  bytes before either conversion pass. `textutil` cannot load remote
  subresources, and the remaining Pandoc stages run in its sandbox.
- ZIP packages reject entries that would overwrite one another on a
  case-insensitive file system, including names that differ only by Unicode
  case folding or a trailing directory slash.
- Explicit output paths cannot enter an RTFD source package merely by changing
  letter casing.
- XLSX cell references with overflowing column values are rejected. Expanded
  hyperlink text and final Markdown or TSV output have independent size limits,
  while legacy XLS parsing stops at the workbook globals end record.
- ODM section links and names are accepted only from their declared XML
  namespaces. Nested note text keeps natural word boundaries without inserting
  spaces before punctuation.
- Asset rewriting recognizes only valid Markdown code fences and correctly
  resumes after thematic breaks, so later image links are neither skipped nor
  rewritten inside code.

## Installation reliability

- Cleanup records a CLI link even if interruption arrives immediately after the
  link was created, so the partial installation cannot be left behind.
- A rollback remains retryable until the staged replacement app has actually
  been removed.
