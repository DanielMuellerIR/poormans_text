# Poor Man's Text 0.8.4

This maintenance release restores conversion of documents that are selected
through a symbolic link, hardens the package and staging paths against input
that changes while it is being read, and makes two conversion results correct
and repeatable.

## Symbolic links

- Documents selected through a symbolic link convert again in every format.
  Only RTF worked before; DOCX, DOC, ODT, ODS, XLSX, XLS, and RTFD reported a
  missing package or a file that is not readable.
- A master document behind a link resolves its sections next to the real
  master, where they are stored, instead of next to the link. Content,
  attachments, and warnings of one conversion always come from the same
  package.

## Package and input checks

- ZIP entries that describe a symbolic link are rejected regardless of the host
  system named in the archive. The check previously applied to Unix archives
  only, while the common writers mark their archives as MS-DOS.
- An entry name is checked in both readings: the raw header name and the name
  from a Unicode path field. Both must be safe paths, and both must agree on
  whether the entry is a file or a directory. An entry can therefore no longer
  skip the size and checksum verification by appearing as a directory under one
  name only, and no name that leaves the package can hide behind a harmless
  one.
- The checks of a package and the bytes that are read now come from a single
  file descriptor, so a source that is exchanged in between cannot pass a check
  it does not satisfy.
- A named pipe or a device file is rejected as input instead of leaving the
  conversion waiting without a time limit.

## Conversion results

- Hyperlink ranges of a workbook share one scan budget across all its sheets. A
  spreadsheet within every documented limit could otherwise occupy detection and
  conversion for a long time.
- Master documents keep a single space where an explicit space meets a note
  paragraph. A second space was inserted before.
- Attribute selection is deterministic when a document assigns two prefixes to
  the same namespace. The same file previously converted or failed at random
  between runs.
