# Poor Man's Text 0.9.0

This release removes two ways in which content could be lost during a
conversion, keeps large photos importable, and filters hyperlink targets taken
from spreadsheets.

## Images

- An image frame above the OCR pixel limit is now scaled down for text
  recognition instead of failing the whole import. A 24-megapixel photo
  converts normally and reports `image.ocrDownscaled`. The stored asset remains
  the untouched original; only what Vision reads is reduced. With several
  frames, the shared 64-megapixel budget is divided evenly.
- Text lines are ordered in two transitive steps — strictly top to bottom, then
  left to right within a band. The previous single comparison was not a strict
  weak ordering, so the same three lines could produce three different orders.

## PDF

- A page with little embedded text keeps that text when local OCR returns
  nothing or fails. Such a page was previously published empty, together with
  the inaccurate note that it contained no text at all.

## Spreadsheets

- Hyperlink targets are limited to `http`, `https`, `mailto`, `file`, and
  targets without a scheme — relative paths next to the workbook and
  sheet-internal `#` targets. A `javascript:` or `data:` target is dropped with
  a visible loss warning while the cell text remains. A single letter before the
  colon counts as a Windows drive, so `C:\Reports\2026.xlsx` from a legacy XLS
  file moniker survives.
- A cell keeps its first hyperlink target when a second hyperlink element for
  the same cell carries no target of its own.
- Legacy XLS detection decides from the eight-byte OLE header whether a file can
  be a spreadsheet at all. An unrelated large input is no longer read into
  memory in full: peak memory for a 512 MB file drops from 549 MB to 13 MB.
- A foreign XLS source is read through a single descriptor instead of being
  mapped, so a sync service replacing the file during detection can no longer
  end the process with `SIGBUS`.

## Rich text and Markdown output

- The 256 MiB rich-text size limit now also applies to the `TXT.rtf` inside an
  RTFD package, not only to a standalone RTF file.
- Setext underlines and tilde fences in literal source text are escaped. A line
  of `=` characters from a PDF or OCR page can no longer turn the line above it
  into a heading, and `~~~` can no longer open a code block.

## Reading and staging

- Every conversion path stages its input from the resolved source path. A
  symbolic link changed between detection and staging can no longer swap the
  converted document.
- Opening, inspecting, and reading a source file is one shared implementation
  across the staging, ZIP, rich-text, and PDF paths. The PDF signature check
  gains the protection it lacked: a named pipe supplied as input no longer
  blocks the conversion without a time limit.
